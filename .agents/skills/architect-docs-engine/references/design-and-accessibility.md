# Design and accessibility

Inspect existing tokens, components and brand before proposing a visual system. For a new interface, mark every value Proposed and specify concrete colors (hex/OKLCH), type scale, spacing/grid, component states, responsive behavior, theme behavior and transition parameters. Contrast targets must be checked against the selected colors; do not claim conformance based on intention alone.

For each applicable primary screen document loading, empty, populated, success, error, disabled and destructive-confirmation behavior as relevant. Include keyboard operation, visible focus, semantic names, screen-reader feedback, reduced motion, zoom/reflow and accessible error association. Avoid prescribing UI to a backend/CLI project; explain that visual screens are N/A and document its actual operator/developer interaction.
